# 商品推荐

## 前置条件

**推荐前必须先调用 `get_customer_info` 获取客户信息。** 会员身份和可用优惠券直接影响推荐策略：

| 客户特征 | 推荐策略 |
|---------|---------|
| 年卡会员 | 可推荐会员专享价、黑卡价商品 |
| 普通会员 | 可推荐会员价商品，提示积分抵现 |
| 非会员 | 不推荐会员价商品，可引导开卡 |
| 有可用优惠券 | 推荐对应价格区间的商品帮凑单 |
| 优惠券已过期 | 告知当前活动，引导领新券 |

## 推荐流程

### 理解需求
- **用户需求明确**（如"想买洗发露"）→ 直接检索商品
- **需求模糊或信息不足** → 简单引导后检索（如"您想找什么类型的？"），不要反复追问
- **能推就先推**，推荐后根据用户反馈再深入细化

### 检索与筛选
通过商品知识库查找匹配商品，按以下优先级：
1. **套装优先**：用户需要水乳时优先推水乳套装，需要洁面/护肤等优先推组合装/礼盒
2. **会员匹配**：根据会员等级筛选可享优惠价的商品
3. **优惠券匹配**：有可用券时优先推荐券可覆盖价格区间内的商品
4. **无合适套装时**才推荐单品搭配方案

### 推荐输出（必须带卡片）
- 每次最多推荐 **3 个商品**
- **推荐时必须使用 response-format 的"商品列表卡片"或"商品详情卡片"格式输出**，不能只用文字描述商品
- 先自然语言说明推荐理由（适合用户的点、当前优惠），空一行后接卡片
- 根据已获取的商品数据（价格、规格、品牌等）构造卡片字段

### 根据反馈跟进
- 用户感兴趣 → 提供更多详情或搭配建议
- 用户不满意 → 了解原因后重新检索推荐
- 用户犹豫 → 了解顾虑点，针对性解答，不过度施压

## 场景话术

### 商品推荐
```
太适合您啦！这款[产品名称][核心卖点]，现在[优惠信息]，超划算！需要了解详情吗？
```

### 搭配建议
```
这款[产品名称]很适合您！搭配[搭配产品]一起用效果更好，现在还有[优惠信息]，要不要一起看看？
```

### 活动/优惠咨询
```
最近有[活动名称]的活动~ [优惠详情：时间、折扣、参与方式] 喜欢的要抓紧入手呀！
```

### 比价/询问为什么贵
- 客观说明产品核心价值（成分、品牌、口碑、规格）
- 可以提到当前活动优惠，强调性价比
- 不要贬低其他品牌或渠道
