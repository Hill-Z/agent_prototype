# 【UAgent】模型配置优化

任务号：RD-6854

## 一、背景及竞品判断

- Claude Code：用户选择当前或默认模型，并支持有序备用模型；子 Agent 默认继承主会话模型，也允许高级覆盖。
- Copilot Studio：以选择主模型为主，通过通用、深度、自动等标签帮助客户理解差异，调度与故障切换由平台处理。
- Dify：支持工作流节点逐个选择模型，更适合专业工作流编排，不适合作为普通 Agent 的默认配置方式。

UAgent 参考 Claude Code：客户只选择模型和优先级，系统负责能力校验与故障切换。该方案同时适用于当前单 Agent 和后续多 Agent 架构。

## 二、方案详情

客户配置一个有顺序的模型池：1 个主模型，最多 2 个备用模型。

| 配置项 | 规则 |
|---|---|
| 主模型 | 必填，正常请求优先使用 |
| 备用模型 | 选填，最多两个，按顺序切换 |
| 模型顺序 | 支持调整，第一位始终为主模型 |
| 模型能力 | 展示通用、深度推理、快速、工具调用、视觉等标签 |
| 模型参数 | 每个模型独立配置，默认使用平台推荐值 |
| 重试次数 | 0–3 次，重试后仍不可用再切换备用模型 |

模型不能重复选择，模型池至少保留一个模型。模型不可用或不满足智能体能力要求时，需要在发布前提示并阻止发布。

每个模型提供独立的“参数设置”。默认不要求客户填写；展开后只展示该模型支持的温度、Top P、最大输出等参数。切换到备用模型时，使用该备用模型自己的参数，不能沿用主模型参数。

单 Agent 直接使用自己的模型池；多 Agent 中，子 Agent 默认继承父 Agent 的模型池，必要时可单独覆盖。

## 三、系统执行

1. 发布前检查模型是否支持智能体需要的工具调用、视觉、结构化输出和上下文长度。
2. 运行时优先使用主模型；发生超时、服务过载、Provider 5xx 或空响应时，先重试，再按顺序切换备用模型。
3. 鉴权失败、欠费、参数错误、内容安全拒答和上下文超限不切换模型，直接返回明确错误。
4. 每次运行记录计划模型、实际模型、重试次数、切换原因、Token 和耗时。
5. 标题生成、上下文压缩等平台内部任务由系统自行选择模型，不增加客户配置负担。

## 四、验收标准

1. 客户可配置 1–3 个不重复的模型，并调整优先级。
2. 每个模型独立保存参数；未配置时使用该模型推荐值。
3. 主模型可用时始终优先使用；不可用时按配置顺序切换。
4. 不兼容智能体能力的模型无法发布。
5. 单 Agent 可直接使用，子 Agent 默认继承并支持单独覆盖。
6. 页面展示、调试日志和实际调用模型保持一致。
