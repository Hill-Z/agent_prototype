# 【UAgent】知识发现优化

任务号：RD-6849

## 一、背景与价值

知识发现没有被用起来，卡在两件事上。

第一，**运营不敢采纳抽出来的候选知识**。列表里只有标准问题和推荐答案，看不出这条知识是从哪段对话抽出来的、哪个客服说的、有没有依据，抽出来一堆也没人敢往知识库里放。这是"敢不敢采纳"的决定性因素。

第二，**抽取流程太依赖人工，跑不起来**。当前设计要运营选智能体、选客服账号、选时间范围，再手动发起一次抽取任务，等于把"什么时候抽、抽多久"的运维负担压给了运营。抽取本应由后台自动完成：客户只在每个智能体上开一个开关，系统按周期自己跑，运营只负责审核。

本需求参考 Intercom 的 Unresolved Questions：每条建议带触发它的会话原文，审核人据此判断；Zendesk 与 eGain 的同类能力同样以"来源可追溯 + 攒够门槛才推"为核心。

## 二、目标与范围

### 2.1 本期目标

- 每个智能体一个开关，打开后由后台按周期自动抽取，客户不创建任务、不配时间范围。
- 运营只做审核：采纳写入知识空间，或忽略。不做配置之外的运维。
- 每条候选都能追溯来源会话原文，支撑"敢采纳"。
- 不是每条都推：去重、聚类、质量门槛通过后才生成待处理候选。

### 2.2 适用场景

- 所有已开启开关的智能体，其转人工后的已结束会话。
- 人工客服给出明确回答、可整理成标准问答的会话。

### 2.3 不在本期

- 不做自动采纳，所有知识必须人工审核后才生效。
- 不做知识库本身的编辑功能，采纳后怎么改归知识库模块。
- 不做客服侧入口，只有运营侧。
- 不做"答了但答得不好"的缺口，本期只覆盖转人工的会话。

## 三、角色与用户流程

### 3.1 角色分工

- **客户/管理员**：在设置页为每个智能体打开或关闭知识发现开关，配置该智能体的抽取条件。
- **运营（知识运营者）**：审核待处理候选，查看来源对话、编辑问题与答案、选择知识空间采纳，或忽略。
- **运营查看者**：只读列表与详情。
- **后台**：按周期自动抽取、去重、聚类、质量判断，生成待处理候选。

### 3.2 正常流程

1. 客户在设置页为一个或多个智能体打开知识发现开关。
2. 后台按周期自动运行，取该智能体**转人工后的已结束会话**，不需要客户指定时间范围。
3. 抽取「问题 + 答案」：答案取人工客服的回复原文，模型只做去 PII 与改写润色。
4. 与知识库已有内容比对去重，重复的丢弃；候选之间再互相比对合并。
5. 用向量相似度做增量聚类，问法不同、意思相同的问题归入同一簇并更新质心；同一簇攒够推送门槛（默认 5 条）且置信度达标，才生成待处理候选。
6. 运营在列表看到候选，点开详情核对来源对话。
7. 运营编辑标准问题与推荐答案，选择目标知识空间后**采纳**；不认可的**忽略**。全程保留来源、处理人和处理时间。

## 四、模型与规则

### 4.1 核心字段

| 字段                | 类型                         | 说明                             |
| ----------------- | -------------------------- | ------------------------------ |
| 发现 ID             | string                     | 候选唯一标识                         |
| 标准问题              | string                     | 模型改写后的标准问句，待处理状态可编辑            |
| 推荐答案              | string                     | 取自人工客服回复原文，待处理状态可编辑            |
| 相似问法 / 聚类 ID      | string[] / string          | 同一簇内的其他问法；簇内条数决定是否达到推送门槛       |
| 置信度 / 置信度解释       | number / string            | 后端质量分及其计算依据，只读，运营不可手工修改        |
| 来源会话              | object[]                   | 主会话 ID、来源智能体、客服系统账号、参与人、原始对话片段 |
| 抽取规则版本            | string                     | 生成该候选时所用的智能体级提示词与阈值版本          |
| 状态                | enum                       | `待处理 / 已采纳 / 已忽略`              |
| 目标知识空间 / 知识 ID    | string                     | 采纳成功后的写入结果                     |
| 处理人 / 处理时间 / 忽略原因 | string / datetime / string | 审核留痕；忽略时可选填原因                  |

### 4.2 状态流转

`待处理 → 已采纳 / 已忽略`，终态不可回退。已采纳、已忽略不允许再次编辑；如需纠错，到知识库编辑或由管理员执行重新打开（本期不提供普通用户入口）。

### 4.3 质量与去重规则

- 置信度是后端质量分，不由运营手工修改。与现有知识达到去重阈值的候选不进入待处理列表，记录为"重复过滤"；低于最低置信度或最低相似会话数的候选进入**内部观察池**，不展示给运营。
- 去重分两层：① 与知识库已有内容比对，相似度超过阈值即判定"已有"，不重复抽；② 候选之间互相比对，同一批里重复的合并。聚类用向量相似度增量聚类：新问题与已有簇质心比对，超过阈值并入并更新质心，否则新建簇。
- 阈值必须用自有数据校准：取 100–200 对人工标注样本，在参考区间内按 0.01 扫描（去重业界参考 0.85–0.92，聚类 0.70–0.90，来自不同 embedding 模型，只能证明量级不能照抄），取准确率与召回率平衡最好的点。
- 阈值是租户配置，必须记录当时版本，不能用新阈值反向改变历史结果；换 embedding 模型后阈值必须重新校准。

## 五、页面与交互

**列表页**

- 状态 Tab：全部、待处理、已采纳、已忽略，数字为当前租户全部数量，不受当前页影响。
- 筛选项：关键词/关联会话 ID、智能体、置信度区间、发现时间（近 7/30/90 天、自定义）。开始日期不得晚于结束日期；所有筛选变化均回到第 1 页。
- 列字段：标准问题、推荐答案摘要、置信度、相似会话数、来源智能体、发现时间、状态、操作。
- 复选框只选择当前页；切页保留已选项并显示总选择数。仅"待处理"可批量采纳/批量忽略；混选终态时禁用操作并说明原因。
- 分页默认每页 20 条，可选 20/50/100；后端分页，返回总条数。空结果展示"清除筛选"，接口失败展示重试。

**详情页**

- 左侧"提取的知识"：标准问题、相似问题、推荐答案可在待处理状态编辑；置信度及计算依据只读。
- 左侧"关联信息"：发现 ID、关联会话 ID、callId、智能体、客服系统账号、发现时间、相似会话数。
- 右侧展示完整的转人工前后对话，明确区分用户、智能体、人工客服及时间；敏感信息按权限脱敏。
- 点击"采纳"先选择目标知识空间，再确认写入；成功后状态变为已采纳并记录知识 ID。点击"忽略"须二次确认，可选忽略原因。

**设置页（知识发现设置）**

- 每个智能体一个开关，打开即纳入自动抽取范围；关闭只停止后续抽取，不删除已有候选。
- 每个智能体单独配置业务范围、抽取要求、不抽取内容；保存形成提示词版本，后续候选记录所用版本。
- 抽取条件：每日/每周、最低置信度、最低相似会话数、仅使用人工明确回答、用户确认解决时加权。
- 页面只有开关和抽取条件，不提供时间范围选择、任务 ID、手动补跑等入口。删除智能体绑定不影响历史数据。

## 六、前后端任务

### 6.1 前端

- 对接服务端筛选、分页、跨页选择与批量操作，仅对待处理项开放动作；完成详情编辑、来源会话、相似会话、采纳时选择知识空间、忽略确认及终态只读。
- 全部操作文案使用"采纳/忽略"，状态使用"待处理/已采纳/已忽略"；设置页读取真实智能体和客服账号，保存智能体级开关、提示词版本与抽取条件，不出现任务发起相关控件。

### 6.2 后端

- 建立自动抽取调度：按智能体开关和周期运行，从转人工的已结束会话采集，完成抽取、PII 处理、去重、聚类、质量门槛和候选持久化；抽取失败可重试，同一智能体、账号、周期已有运行中任务时阻止重复执行。
- 提供列表/详情/来源会话/批量采纳/批量忽略/设置接口，所有写操作做租户隔离、权限校验和审计；采纳采用事务或可恢复工作流，知识写入成功后才能更新候选状态，幂等键为"发现 ID + 目标知识空间"。
- 对话快照按数据保留策略存储；源会话删除后仍保留审核所需脱敏片段，超过期限只展示"来源已过期"。

## 七、边界与异常

- **权限**：运营查看者只能看列表/详情；知识运营者可编辑、采纳、忽略；管理员可配置抽取规则并重新打开误处理项。
- 用户只能操作其有权限的知识空间；批量采纳中有无权限空间时整批阻止，不做静默部分采纳。
- 同一候选被两人同时处理，后提交者收到"已被处理"并刷新状态，不覆盖先处理结果。
- 目标知识空间被删除/停用时采纳失败，候选保持待处理；已写入知识但回写状态失败时由幂等补偿修复。
- 源会话无人工有效回答、只有排队/取消、答案包含一次性补偿或个人隐私时不得生成候选。
- 批量操作上限 100 条；超过上限提示缩小范围。批量结果返回成功与失败明细。

## 八、验收标准

1. 打开某智能体开关后，无需任何人工发起动作，后台按周期产生待处理候选；关闭后不再产生新候选，历史候选仍可处理。
2. 列表可按状态、智能体、置信度、日期和关键词组合筛选，服务端分页总数正确。
3. 仅待处理项可编辑、采纳、忽略；已采纳/已忽略不可重复处理。
4. 详情能看到关联会话 ID、转人工前后完整角色化对话、抽取规则版本和置信度依据。
5. 采纳前必须选择有权限的知识空间；成功后可跳转新知识，重复提交不产生重复知识。
6. 跨页选择、批量采纳和批量忽略返回逐条结果；并发处理不会覆盖他人结果。
7. 重复过滤与低于门槛的候选不展示给运营，进入内部观察池。
8. 页面与文档统一使用"采纳/忽略"和"待处理/已采纳/已忽略"，不出现"入库/放弃"。
9. 所有详情和操作符合租户隔离、敏感信息脱敏和审计要求。

## 九、原型对应与当前差距

**原型入口**：`http://127.0.0.1:4175/?view=discovery`

**改动后应达到的状态**：原型覆盖状态 Tab、筛选、自定义日期、分页、当前页全选、批量采纳/批量忽略、详情来源对话、选择知识空间、智能体级开关与抽取条件，主流程可讲清；列表页不出现手动抽取入口。

**当前可用程度：部分可用。** 主流程可用，但原型正由另一侧同步改造为新命名与自动抽取，以下为待补差距：

- 仍保留客户手动发起抽取的旧入口和"入库/放弃"旧文案，需改为后台自动抽取与"采纳/忽略"。
- 服务端分页与真实数量、跨页选择规则、相似会话列表、忽略原因、已采纳知识跳转、权限与并发提示尚未实现。
- 设置页仍是任务式配置，尚无智能体级开关的自动抽取语义；抽取链路为前端模拟，正式实现必须由后台按智能体开关周期自动运行。
