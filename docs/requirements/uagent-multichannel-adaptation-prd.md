# 高级智能体多渠道消息适配与差异化回复

## 1. 需求背景

高级智能体需要接入 Udesk IM、网页插件及海外 IM。不同渠道在入站消息结构、附件获取、可发送消息类型、卡片协议、Markdown 支持、回复窗口和失败码方面存在差异。当前若由 Agent 直接理解各渠道原始协议，会导致 Prompt、Skill 和业务工具与渠道强耦合，新增渠道时需要重复改造 Agent。

本需求建设渠道适配层和统一消息模型，并允许配置 Agent 在不同渠道使用不同回复内容、消息形态和降级策略。

## 2. 目标

1. 将渠道原始消息统一转换为 Agent 可消费的标准消息。
2. 将 Agent 输出转换为渠道支持的文本、媒体或结构化消息。
3. 将渠道类型、账号、能力和用户标识作为受控运行时上下文提供给 Prompt、Tool 和 Memory。
4. 支持按渠道、账号、消息类型、语言和渠道能力配置差异化回复规则。
5. 渠道不支持目标消息形态或发送失败时自动降级，并记录完整 Trace。

## 3. 本期范围

首批支持：Udesk IM、网页插件、WhatsApp、X Direct Messages。

本期包含统一适配框架、渠道能力管理、消息预览、差异化规则、降级与测试能力。后续渠道通过新增 Adapter 和 Capability Profile 接入，不修改 Agent Loop。

不包含各渠道账号采购、渠道侧商业资质申请和客服工作台改造。

## 4. 前端功能

### 4.1 渠道列表

- 展示渠道名称、账号、连接状态。
- 支持新增渠道、编辑账号与鉴权配置、测试连接。
- 鉴权密钥仅支持重新填写，不回显明文。
- 连接状态包括：已连接、待授权、异常、已停用。

### 4.2 消息能力

每个渠道展示三组只读能力：

- 接收：文本、图片、音频、视频、文件、位置、联系人、Reaction 等。
- 发送：文本、图片、音频、视频、文件、模板、Interactive 等。
- 原生结构：按钮、列表、订单卡片、商品、Flow 等。

能力由后端渠道能力档案返回，不允许前端手工声明渠道实际不支持的能力。

### 4.3 消息预览

- 原生预览：展示当前渠道真实可发送形态。
- 降级预览：展示渠道不支持或发送失败时的文本、链接或编号选项形式。
- 支持复制标准消息 JSON 和发送测试消息。

### 4.4 差异化回复规则

规则包含：名称、优先级、生效范围、条件、动作和状态。

条件支持：

- 渠道类型、渠道账号。
- 消息类型、会话阶段、首次会话。
- 用户语言、地区和工作时间。
- 渠道是否支持指定消息能力。

动作支持：

- 注入渠道专属 Prompt 片段。
- 指定短文本、普通文本或结构化消息。
- 选择渠道模板或卡片模板。
- 修改称呼、语气、链接形式和消息条数。
- 指定不支持时的降级方式或转人工。

规则优先级：账号规则高于渠道规则，渠道规则高于 Agent 默认配置；同层按优先级从高到低执行。互斥动作只采用最高优先级规则，可合并的 Prompt 片段按优先级拼装。

### 4.5 上下文变量

提供受控变量：

- `channel.type`
- `channel.account_id`
- `channel.capabilities`
- `user.channel_user_id`
- `conversation.channel_conversation_id`
- `conversation.consent_status`

变量按 Prompt、Tool、Memory 分别授权，未授权变量不能进入对应模块。

## 5. 后端设计

### 5.1 入站统一消息模型

渠道 Adapter 将 Webhook 或拉取消息转换为：

```json
{
  "event_id": "provider_event_id",
  "channel": {"type": "whatsapp", "account_id": "acc_01"},
  "conversation": {"id": "conv_01", "reply_window": "open"},
  "sender": {"channel_user_id": "user_01"},
  "parts": [
    {"type": "text", "text": "查询订单"},
    {"type": "image", "asset_id": "asset_01", "mime_type": "image/jpeg"}
  ],
  "received_at": "2026-07-21T10:00:00+08:00"
}
```

媒体由接入层下载并转存为平台 `asset_id`，Agent 不直接依赖短期渠道 URL。渠道原始报文只保存在受限 Trace 中。

### 5.2 Agent 输出模型

Agent 输出为有序消息数组，每条包含 `type`、`content`、`actions`、`fallback` 和 `client_message_id`。Agent 不直接生成渠道 SDK JSON。

### 5.3 运行链路

```text
渠道事件 -> Adapter 标准化 -> 去重与排序 -> 上下文注入
-> Agent Loop -> 回复规划 -> 渠道 Renderer -> 能力校验
-> 原生发送或降级 -> 发送结果 -> Trace
```

### 5.4 能力与降级

- Capability Registry 以渠道、API 版本、账号能力为维度维护。
- Renderer 发送前验证消息能力、会话窗口和必填字段。
- 不支持时按配置降级为文本、链接、编号选项或人工处理。
- 原生发送失败仅对可降级错误执行一次降级；鉴权、限流等错误进入重试或告警，不重复生成 Agent 回复。

### 5.5 可靠性

- 使用 `event_id` 实现入站幂等。
- 使用 `client_message_id` 实现出站幂等。
- 同一会话按渠道消息序号串行处理，不同会话并行处理。
- 发送重试采用指数退避，并遵守渠道限流和回复窗口。
- 密钥由平台密钥服务托管，配置、日志和 Trace 不记录明文。

## 6. Trace 与指标

每次运行记录：渠道、账号、入站消息类型、标准化结果、命中规则、目标消息类型、实际发送类型、是否降级、渠道 message_id、错误码、重试次数和各阶段耗时。

核心指标：接收成功率、发送成功率、结构化消息使用率、降级率、发送 P95、渠道错误分布和规则命中率。

## 7. 验收标准

1. 四个首批渠道均可将文本及其支持的媒体转换为统一消息模型。
2. 同一 Agent 在不同渠道可命中不同回复规则，且 Trace 可解释命中原因。
3. Agent 输出不包含渠道 SDK 私有 JSON，由 Renderer 生成渠道请求。
4. 渠道不支持结构化消息时按配置降级，消息顺序不变且不重复发送。
5. 重复 Webhook 不会触发重复 Agent Run 或重复回复。
6. 渠道鉴权信息不在页面、日志和 Trace 中明文展示。
7. 测试连接、规则测试、原生预览和降级预览可正常使用。
