# 【高级智能体】多模态输入支持（图片理解与语音识别）

## 1. 需求背景

高级智能体目前主要以文本作为用户输入，无法在统一链路中处理客户发送的图片和语音。客服场景中大量问题依赖错误截图、订单凭证、产品照片及语音描述，需要补齐调试、渠道接入、识别、Agent处理和可观测能力。

本期建设图片理解与语音识别的基础能力，优先覆盖高级智能体调试和正式IM渠道输入，不扩展视频、文档理解、语音回复等能力。

## 2. 产品目标

1. 配置人员可在高级智能体调试窗口上传图片，并验证Agent对图片及图片文字的理解结果。
2. 配置人员可在调试窗口录制语音，ASR完成后将文字自动回填输入框，允许修改后再发送。
3. IM渠道可接收客户发送的图片和语音，完成媒体下载、标准化、识别并交给Agent处理。
4. 调试视图可展示识别状态和识别结果，客户侧不暴露模型、ASR、工具等技术过程。
5. 识别过程具备基础失败提示、Trace事件和耗时统计。

## 3. 本期范围

### 3.1 包含

- 图片输入：JPG、PNG、WEBP。
- 调试端图片选择、预览、删除、与文字共同发送。
- 图片理解、OCR文字提取及识别结果展示。
- 调试端浏览器录音、录音状态、ASR识别、文字回填与修改后发送。
- IM渠道图片获取、内部存储、图片理解后进入Agent。
- IM渠道语音获取、格式转换、ASR后自动进入Agent。
- 图片与文字组合输入。
- 基础配置、错误处理、Trace和统计。

### 3.2 不包含

- 视频理解。
- PDF、Word等文件理解。
- 图片生成、语音生成和语音回复。
- 实时流式ASR和边说边识别。
- 说话人分离、情绪识别、声纹识别。

## 4. 用户场景

### 4.1 调试人员上传图片

调试人员上传支付失败截图，输入“帮我看一下为什么失败”。系统理解图片内容、提取OCR文字，并由Agent结合问题生成回答。

### 4.2 调试人员使用语音输入

调试人员点击“语音”开始录音，结束后系统进行ASR。识别文字自动填入输入框，调试人员可修正错别字或补充上下文，然后点击发送。语音不会作为附件发送给Agent。

### 4.3 客户通过IM发送图片

客户在WhatsApp、网页IM等渠道发送图片或图片加文字。渠道适配器获取媒体并转存，图片理解完成后与客户文字共同进入Agent。

### 4.4 客户通过IM发送语音

客户发送语音消息。系统下载并转码后执行ASR，将转写结果作为客户输入自动进入Agent，不要求客户确认或二次发送。原始语音继续保留在会话消息中供播放和人工接管查看。

## 5. 配置设计

高级智能体编排页增加“多模态输入”。

### 5.1 图片识别

| 配置项 | 说明 | 默认值 |
|---|---|---|
| 接收并识别图片 | 关闭后调试入口禁用，IM图片不进入图片理解 | 开启 |

图片直接使用当前Agent模型。模型是否支持图片由平台模型能力注册表判断，不向Agent配置人员提供独立图片模型或图片数量配置。

### 5.2 语音与音频识别

| 配置项 | 说明 | 默认值 |
|---|---|---|
| 接收并识别语音和音频 | 控制调试语音输入及IM语音识别 | 开启 |
| ASR服务 | 选择平台内置或已接入的ASR服务 | Udesk ASR |
| 识别语言 | 自动识别、中文、英文 | 自动识别 |

音频时长、采样率、声道、转码格式、重试等工程参数由平台统一管理，不在Agent配置页暴露。

## 6. 调试端前端设计

### 6.1 图片输入

1. 输入框工具栏展示“图片”。
2. 点击后打开系统文件选择器，支持JPG、PNG和WEBP。
3. 选择后在输入框上方展示缩略图、文件名、大小和删除按钮。
4. 图片可与文字一起发送；没有文字时也允许发送。
5. 发送后用户消息区域展示原图缩略图和输入文字。

### 6.2 语音输入

1. 点击“语音”后弹出录音浮层并开始计时。
2. 浮层展示录音状态、时长、动态波形、取消和完成录音。
3. 点击完成后切换为“正在识别语音”。
4. ASR完成后关闭浮层，把转写文字自动填入输入框。
5. 用户可直接编辑回填文字，点击发送后按普通文本输入进入Agent。
6. 调试端不生成待发送的音频文件，也不把原始录音作为Agent附件。

### 6.3 调试过程

图片处理中的当前状态包括：

- 正在读取图片。
- 正在理解图片。
- 正在整理回复。

完成后折叠展示“已识别N张图片”，展开后展示：

- 图片内容摘要。
- OCR文字。
- 使用模型。
- 图片理解耗时。
- OCR置信度。

语音ASR在发送前完成，因此Agent Run中不重复展示ASR步骤。ASR状态展示在输入区录音浮层中。

## 7. 正式IM处理设计

### 7.1 统一消息结构

渠道适配器将不同IM消息转换为统一结构：

```json
{
  "message_id": "msg_123",
  "conversation_id": "conv_456",
  "sender_id": "customer_001",
  "channel": "whatsapp",
  "text": "帮我看一下这个报错",
  "attachments": [
    {
      "attachment_id": "att_001",
      "type": "image",
      "mime_type": "image/jpeg",
      "internal_url": "media://tenant/att_001",
      "size": 182033
    }
  ]
}
```

### 7.2 图片链路

渠道收到图片 → 使用渠道凭证下载 → 转存租户隔离的内部存储 → 校验类型和大小 → 调用图片理解模型 → 将图片、用户文字及识别结果组装为Agent输入。

文字与图片必须共同提交给多模态模型，避免先生成通用图片描述后丢失用户问题语境。

### 7.3 语音链路

渠道收到语音 → 下载媒体 → 识别真实格式 → 转换为ASR标准格式 → ASR转写 → 将转写结果作为客户输入自动进入Agent。

正式IM与调试端不同：

- 不回填给客户修改。
- 不发送“ASR结果”系统消息。
- 客户侧只保留原始语音消息、正在输入状态和Agent最终回复。
- 原始语音与转写文字在会话记录中关联，人工接管可播放原音并查看转写。

## 8. 后端模块

### 8.1 Channel Media Adapter

- 解析渠道媒体ID和消息类型。
- 使用渠道凭证下载图片或语音。
- 处理临时地址过期、下载重试和渠道错误码。
- 输出统一附件结构。

### 8.2 Media Storage

- 按租户隔离保存媒体。
- 生成内部附件ID和短期签名访问地址。
- 执行生命周期清理。

### 8.3 Media Preprocessor

- 校验真实MIME类型、大小和数量。
- 图片格式标准化。
- 将AMR、SILK、OGG/OPUS、MP3、M4A等语音转换为ASR支持格式。

### 8.4 Recognition Service

提供统一能力：

```text
recognizeImage(attachment, userText, config)
transcribeAudio(attachment, config)
```

统一屏蔽具体视觉模型和ASR厂商的接口差异、超时、错误码与重试。

### 8.5 Multimodal Message Composer

- 合并客户原始文字、图片引用、图片理解结果和ASR结果。
- 标记识别内容为非可信用户输入，不能作为系统指令。
- 生成Agent Loop统一输入。

## 9. 接口建议

### 9.1 调试图片上传

```http
POST /api/agents/{agent_id}/debug/attachments
Content-Type: multipart/form-data
```

### 9.2 调试语音ASR

```http
POST /api/agents/{agent_id}/debug/asr
Content-Type: multipart/form-data
```

响应：

```json
{
  "transcript": "我想查询一下昨天购买的订单什么时候发货。",
  "language": "zh-CN",
  "confidence": 0.94,
  "duration_ms": 8200
}
```

### 9.3 发起调试Run

```json
{
  "text": "帮我看一下为什么失败",
  "attachment_ids": ["att_001"]
}
```

录音转写已经进入`text`，不会作为音频附件重复发送。

## 10. 错误处理

| 场景 | 处理 |
|---|---|
| 浏览器无麦克风权限 | 提示允许麦克风权限，可继续使用文字输入 |
| 录音设备不可用 | 提示检查麦克风设备 |
| ASR失败 | 保留输入框现有文字，提示重新录音 |
| 图片格式不支持 | 上传阶段阻止并说明支持格式 |
| 图片数量超限 | 保留允许数量，其余不上传并提示 |
| 渠道媒体下载失败 | 自动重试2次，失败后返回可配置兜底回复 |
| 图片理解失败 | 重试一次；仍失败则提示重新发送或文字描述 |
| IM语音ASR低置信度 | Agent执行敏感操作前必须确认关键业务字段 |

## 11. 安全要求

- 识别真实MIME类型，不只依赖扩展名。
- 渠道临时URL不得直接传给模型。
- 原始媒体按租户隔离存储。
- 日志只记录内部附件ID，不记录二进制或渠道鉴权URL。
- 图片OCR和ASR文字均属于不可信用户输入，必须经过输入护栏。
- 原始媒体和识别结果遵循会话数据保留期限。

## 12. Trace与统计

新增事件：

- `media.received`
- `media.download.started/completed/failed`
- `media.preprocess.completed/failed`
- `image.recognition.started/completed/failed`
- `audio.asr.started/completed/failed`
- `agent.run.started`

基础指标：

- 图片理解成功率和平均耗时。
- ASR成功率、平均耗时和低置信度占比。
- 渠道媒体下载失败率。
- 多模态请求端到端首响应耗时。
- 各格式失败原因分布。

## 13. 验收标准

### 调试端

- 可配置开启或关闭图片、语音能力，关闭后对应入口禁用。
- 可上传、预览、删除图片，并与文字共同发送。
- 点击语音可进入录音状态并完成录音。
- ASR期间展示识别状态，完成后自动回填文字。
- 回填文字可编辑，点击发送后以文本进入Agent。
- 图片处理完成后可展开查看摘要、OCR、模型和耗时。
- 客户视图不展示图片模型、ASR或工具技术状态。

### IM渠道

- 渠道图片可下载、转存、识别并交给Agent。
- 渠道语音可下载、转码、ASR并自动交给Agent。
- 原始图片和语音在会话中正常展示。
- 人工接管可查看原始媒体和语音转写。
- 识别失败有明确兜底，不允许Agent在无识别结果时凭空回答媒体内容。
- Trace能够区分媒体下载、预处理、识别和Agent运行耗时。

## 14. UI附件

任务附件提供：

- 调试端录音中状态。
- ASR完成后文字自动回填状态。
